# Technical Limitations and Forensic Boundaries

While `rea-image` combines hard cryptographic provenance, statistical frequency forensics, and regional segmentation to reverse-engineer images, certain imaging conditions present fundamental signal limits. Understanding these limitations ensures proper operational use and prevents misinterpretation.

---

## 1. Pixel Scale and Patch Size Limits
- **Patches under 64×64 pixels**: Forensic frequency falloff ($\alpha$), 2D FFT spectral peak detection, and DCT $8\times 8$ grid alignment require adequate spatial support. Segments or crops smaller than $64\times 64$ pixels lack the statistical sample size for reliable estimation; such regions fallback to flat run or visual heuristic priors.
- **Micro-crops under 16×16 pixels**: Cannot be reliably classified by local forensics alone and inherit parent or global provenance properties.

---

## 2. Heavy Platform Post-Processing and Multiple Re-Saves
- **Multi-pass re-compression**: When an image is repeatedly saved across messaging apps (e.g. WhatsApp $\to$ Twitter $\to$ Instagram), secondary quantization matrices overwrite camera DCT fingerprints. Low ELA residuals occur naturally on re-compressed files, requiring corroboration from flat-run continuity or Poisson noise before concluding vector or graphic design.
- **Aggressive denoise and beauty filters**: Heavy frequency-separation skin smoothing, computational night-mode de-noising, or AI "portrait enhancement" built into smartphone cameras suppress high-frequency sensor noise ($p75 < 1.0$), which can mimic diffusion or 3D shader smoothness.

---

## 3. Screenshots and Display Resampling
- **Sub-pixel display scaling**: Taking a screenshot on retina/HiDPI displays introduces bilinear or bicubic filtering that blurs single-pixel vector boundaries and spreads high-frequency lines across 2–4 pixels.
- **Screenshot-of-Photo / Screenshot-of-AI**: A screenshot of an AI-generated image loses PNG chunks and metadata; the detector must rely on residual synthetic noise, prompt anomalies, or frequency artifacts.

---

## 4. Hardware EXIF and Orientation
- **Pre-normalized EXIF**: Some legacy tools strip or misapply EXIF orientation tags (tags 1 through 8). `rea-image` automatically applies `ImageOps.exif_transpose` upon ingestion, but if an image was manually rotated in an editor without updating or stripping conflicting EXIF tags, edge alignments may shift by 90°.
- **Forged or Spoofed EXIF**: EXIF data is unencrypted text and can be edited with `exiftool`. `rea-image` prioritizes cryptographically signed C2PA / Coalition for Content Provenance and Authenticity manifests over plain EXIF metadata.

---

## 5. Offline Forensics vs. Semantic Understanding
- **Pure Offline Mode**: By default, `rea-image` runs strictly offline with zero external network calls. In this mode, detection relies entirely on deterministic mathematics (FFT falloff, Laplacian residual noise, DCT block grids, run-length encoding). It will not detect semantic AI hallucinations (e.g., a hand with six fingers, gravity-defying architecture) unless the optional online VLM model is explicitly enabled (`--online --vlm <model>`).
- **Gibberish Text**: In pure offline mode without OCR extras (`pytesseract`), pseudo-text glyphs generated by diffusion models cannot be semantically parsed as non-words without OCR or VLM inspection.

---

## 6. Supported File Formats and Decoders
- **Still 2D Rasters Only**: Animated formats (GIF, animated WebP, APNG) and video files are out of scope.
- **Optional Formats (HEIC / AVIF)**: `.heic` and `.avif` formats require system or Python codecs. Install them with `pip install 'rea-image[heic,avif]'`.
